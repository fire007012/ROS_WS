# ROS 停车职责与精简 STM32 对齐（2026-10-17）

本次只检查、修改当前 ROS 工程；没有修改 STM32，也没有连接实际 CAN 发运动帧。保留 WAIT_ACK、原生确认、负 ACK、严重故障、失联、execution_failure 保护。未改变 CAN 报文字节格式和轮序。以下架空步骤尚未进行，本次回归不能代替实机验收。

## 从实际源码确认的决策链

- `path_manager/src/path_tracker_node.cpp` 与 `range_detour.h`：路径跟踪向 `/cmd_vel_external` 发速度，路径结束、取消、里程计过期均输出零；新鲜有效测距触发 `BRAKING → SIDESTEP → BYPASS → EDGE_CLEAR → RETURN`，受阻/停滞/越界停车，失败后要求新路径。无回波不触发近障碍，已发现的障碍仍保留几何记忆。
- `motion_planner/src/cmd_vel_mux_node.cpp`：接收导航、遥控、固定路线及阶段限定的机械臂侧移，按各输入自己的单调时钟接收时间判断超时；发布原始请求 `/cmd_vel_requested`，供距离安全节点判断，再将安全约束后的速度发到 `/cmd_vel_muxed`。
- `robot_navigation/src/distance_safety_node.cpp`：前/左/右/后新鲜有效原始距离减安装内缩，结合请求/实测速度、反应时间、制动减速度、余量与滞回决定减速或零速；转向检查四个方向。无有效回波不会按零距离处理，也不禁止普通导航。
- `motion_planner/src/planner_node.cpp`、`kinematics.cpp`：将仲裁后的 Twist 转为逻辑 `[前、右、后、左]` 四轮 RPM。
- `can_motor_interface/src/can_interface_node.cpp`、`link_health.h`：最终四轮运动出口，独立检查 RPM 输入过期，控制缓存、逐轮即时发送、反馈/ACK 新鲜度与急停互锁。
- `mission_controller.cpp::lockChassis/cancelMissionActions`：任务结束和取消锁底盘；故障发 `/stop_all` 或 `/emergency_stop`。`health_monitor.cpp` 汇总 `/odom`、`/motor_state` 新鲜度，真实故障走急停。

轮序只在 CAN 桥映射一次：逻辑 `[前、右、后、左] → STM32 index [1、0、3、2] → CAN2 物理地址 [2、1、4、3]`；默认方向 `[+1、+1、+1、+1]`，反馈做逆映射。保留该实现。

具体修正：

- 安全限速只能约束仍然有效的上游请求。即使安全节点继续发旧的非零限速，遥控/规划输入过期后也立即零速；安全速度不能增大当前请求或反转方向。命令路径队列取最新一条，锁底盘的进入和退出都清除旧输入。
- CAN 桥直接接收距离停车状态、底盘锁和 `/stop_all`。距离 STOP/命令异常、任务锁同样覆盖直接 `/motor_velocity_cmd` 输入，运行中一次回调提交四轮零速；解除普通停车后要求新输入。故障或取消非零启动缓存时走显式急停。
- 启动前每次只提交一轮 `sync=1`，等待其 `0x102 cmd=01 result=0` 再提交下一轮，四轮全部确认后才 `CACHE_READY`。由于线上没有主机序号/电机索引回显，串行等待避免虚构 ACK 与电机的关联；不按所有 CAN1 帧推算序号。
- `0x112 result=0` 只进入等待启动确认；同一 STM32 序号的 `0x102 cmd=05 result=0` 才允许 RUNNING。该 ACK 表示默认原生 `FF 02 6B` 已确认，既不要求先观察到非零速度，也不表示已到位。ACK/事件任一先到均可关联；重复初始事件不延长截止时间；同序号后续 result=2 不再被 500 ms 时间去重吞掉。启动负 ACK、确认超时直接进入已有急停清缓存路径。
- 每轮原生 F6 ACK 只为尚未完成的发送计时，收到真正 `02` 后移除一项；重复发送不延长旧请求期限，已完成请求不会在空闲时制造超时。`9F` 不冒充默认终态确认。
- 只有四轮各有一份新的原生速度采样才发布下一组 `/motor_state`；`0x101` 缓存重复报告不能更新实测时间戳或启动状态。默认反馈期限仍是 1.0 s，主动补读从半期限起进行；健康空闲约 160 ms 的速度轮询不会因 100 ms 一类过短门限误停。运动占用造成持续超期时仍保护。
- `FFFF + VALID=0` 且无采集 TIMEOUT/I2C/EMERGENCY 标志的正常无回波发布 NaN，持续新序号的诊断为 `no return (normal)`；真正采集错误、重复序号/通信静默超期仍报 ERROR。`0x111` 历史距离不覆盖当前实测；重复有效 `0x110` 不续期。距离安全节点保留消息本来的年龄。
- 删除测距桥里模拟旧 STM32 “前三路 300 mm 全方向停车”的额外门限；四向净空统一交给 ROS 距离安全节点。3/4 只在启用的任务阶段参与机械臂对齐，阶段、配对新鲜度、取消保护保留。

## 两种停车路径与上游断流

普通运行：距离制动/输入过期/任务锁 → 仲裁零速，或 CAN 桥自身的停车门控 → 四轮 `01 idx 00000000 accel 00`。零速提交失败也转急停。

故障/取消缓存：负 ACK、原生 E2/EE、严重驱动状态、真实反馈失联、启动失败/确认超时、发送失败、execution_failure 等 → `triggerEmergencyStop` → 清 ROS 目标 → `MotionInterlock` 锁所有后续运动写入 → `03 FF 00 00 00 00 00 00` → 取消导航、锁底盘并重试停车。修复故障并显式复位后清缓存，要求重新准备；不重放失败或取消的目标。

心跳每 100 ms 独立发送 `09 FF 00 00 00 00 00 00`，不会刷新任何上游输入时钟：

| 输入丢失 | 判断者与默认期限 | 处理 |
| --- | --- | --- |
| `/cmd_vel`、teleop、external、fixed_route | mux 的 `~cmd_timeout_sec=0.5` | 每源独立接收时间过期；没有其他有效运动源时发布零，不接受安全节点单独维持非零 |
| 机械臂阶段侧移输入 | mux 的 `~alignment_cmd_timeout_sec=0.2` | 保持侧移模式并停车，不回退导航 |
| planner 或直接 RPM 发布者 | CAN 桥的 `~command_timeout_sec=0.5` | 运行中下一个命令槽提交四轮零速，之后只刷新零速；心跳继续 |
| 原生四轮反馈、STM32 心跳 ACK/统计 | CAN 桥的 `~heartbeat_timeout_sec=1.0` | 真正过期进入显式急停；缓存报告不续期 |

默认 mux 检查周期约 33 ms，CAN 命令槽约 12.5 ms；0.5 s 是软件检测门限，不是车辆物理停稳时间。Twist/Float32MultiArray 无 Header，所以使用各真实入口接收时的单调时间，而不是下游重复发布的时间。

已确认的启动缓存属于有意等待实体按钮的准备状态，可在心跳正常时等待数秒，不用运行租期将它强制过期。准备期间收到零速、距离停车或任务锁会显式取消非零缓存；按钮释放后若运行输入仍未恢复，桥发四轮零速。缓存确认本身缺失仍在 0.5 s 后急停。

## 架空实测步骤（待执行）

1. 四轮离地，确认 CAN1/CAN2 都是 500 kbit/s；先用 `ip -details -statistics link show can0` 和只读 `rosrun can_motor_interface check_stm32_can.py --device can0` 检查。只运行一个底盘写入节点，保留 WAIT_ACK 和所有保护。用 `candump -L can0` 记录 0x100/101/102/103/110/111/112 和原生扩展应答。
2. 启动 `roslaunch robot_navigation path_smoke_test.launch`（默认保留测距、制动和绕行），不设置 `wheels_lifted:=true`。它限制 10 RPM/0.03 m/s，且初始没有自动路线。观察 `/motor_link_ready`、`/distance_safety/state`、`/cmd_vel_mux/selected_source`、`/motor_state`、`/diagnostics`。无回波应为 NaN 且诊断说明正常无回波，不能被报告成零距离或因此拒绝导航。
3. 初始零速四轮缓存全部确认后，等待至少 3 秒再按真实 STM32 按钮。核对 0x112 的序号与 cmd=05 ACK；初始 result=0 期间不能宣称启动成功，同序号终态成功后才为 RUNNING。若负 ACK 或 result=2，必须看到急停和缓存取消，保留证据后排查，不能反复复位继续运动。默认广播启动的原生确认应为固件地址映射第一项、默认地址 1 的 `FF 02 6B`；`FE 02 6B` 等不能替代。
4. 进入 RUNNING 后选择短程路径或给单一 teleop 源低速命令；先确认默认逻辑/物理轮对应。用真实障碍板产生有效新距离：检查原始值只在 ROS 减一次内缩；近距时 `/distance_safety/state=STOP`、四轮 sync=0 零速；退到释放阈值之外才恢复。遥控不会触发路径绕行；绕行需启用 tracker 路径，前方净空约 0.70 m 触发，观察 BRAKING/SIDESTEP/BYPASS/RETURN；完全架空时可核对轮速和决策，不能宣称真实平面绕障成功。
5. 去掉障碍保持大部分无回波，确认普通导航可运行。随后只暂停当前路径速度发布进程（可对其 PID 发 SIGSTOP，避免 required 节点退出带走整个 launch；确认没有其他备用非零源），保留 CAN 桥、心跳和测距：mux 源断流约 0.5 s 加一周期内应零速。再在独立一次测试中用 SIGSTOP 暂停 planner，保持 mux/CAN 桥运行：桥在自己的约 0.5 s 门限后发送四轮零速。检查之后持续一秒没有旧非零重放。不要用关闭 CAN 桥测试替代上游断流。每次测试结束先请求急停/取消任务，再恢复被暂停的进程并按正常流程重新准备。
6. 请求任务取消或底盘锁，核对所有运动出口为零。故障组按可控方式制造单驱动失联/原生负应答，核对显式急停、四轮运动抑制、execution_failure 诊断仍在；恢复接线后不得自行重放。正常 `0x83`、bit7 掉电记录不能当严重故障。确认错误原因解除、反馈恢复后显式复位，再重新准备并按实体按钮；最后核对四轮实测零速再结束。

架空里程计只能验证轮速闭环；地面制动距离、打滑、安装几何和真实绕障余量仍需独立低速实测。
