# ROS 端 CAN 通信处理（2026-10-16）

范围：按用户要求仅调整 ROS，不修改、编译或烧录 STM32 固件。
车轮架空，方向与轮序沿用已确认结果。通信故障是否解决以持续实机验证为准。

## 已取得的基线

- 60 秒纯接收：32487 个外部报文，无 CAN 错误帧，主机 TX 数未变。
  STM32 三类故障计数保持不变。
- 60 秒心跳和原生速度/状态查询：发送心跳 591 次，成功 ACK 591 次；
  发送查询 1180 次，收到外部报文 35437 个，无 CAN 错误帧。
  四轮末次反馈均为 0 RPM、flags=0x81，故障计数无新增。
- CAN1 发送失败历史计数为 1732，命令排队丢弃为 6、执行失败为 4、
  响应超时为 1；历史值并非当前测试新增故障。
- 此前四帧突发和逐轮 20 Hz 两种速度发送方式都出现过故障。
  当前证据不能唯一确定故障位于物理链路、CANable 或 STM32 内部。

## ROS 调整

`command_publish_rate_hz` 继续表示每轮最高更新频率，默认从 50 Hz 改为 20 Hz。
定时器每 12.5 ms 只处理一轮，不补发积压时隙。每次直接使用 ROS 最新目标。
以实际发送的整数 RPM 合并重复值，目标不变时每 200 ms 刷新一次，
四轮恒定目标约为 20 帧/秒；变化目标上限合计 80 帧/秒。

刷新参数限定 50..250 ms，每轮更新上限限定 10..50 Hz，确保刷新周期留在
原有 500 ms 原生 F6 应答保护内。命令过期仍逐轮发送零速。
急停复位后清空上一次发送记录。按钮前仍按四轮一组准备同步缓存，
合并相同整数目标并限制每轮更新周期，避免更快的运行定时器增加缓存批次。
保留默认物理按钮启动状态机、心跳、
负应答、故障计数、反馈过期和 F6 应答超时保护。

生产节点不添加绕过按钮参数。仅 `/tmp` 中的测试构建允许已授权的架空测试
绕过按钮，最高 20 RPM，故障检查仍开启。

## 实机复验及结论

本轮 `medical_route_stand_20261016_133457`，13:34:57 开始，总耗时约 70.58 秒。
60 秒连续零速闭环通过，随后发布护士台路径 P0→P1；行驶约 0.53 m 后停车，
未到达 P1，也未进入 1 床、3 床和回程段。

- 13:36:05.501 CAN 报告 class=0x0C、protocol=0x10、location=0。
  按本机 Linux `can/error.h`，0x10 为 `CAN_ERR_PROT_BIT1`，即无法发送隐性位。
  这是 CAN 控制器报告的位错误，不是应用层收包超时；不能据此唯一定位器件或线束。
- 13:36:05.616 收到 `03c5060000000000`，CAN1 TX 失败由 1732 增为 1733，
  系统锁存急停。排队丢弃仍为 6、执行失败仍为 4、响应超时仍为 1。
- 四轮原生运动应答地址 2/1/4/3 分别 297/290/296/292 次。
  零速期间每 10 秒约 171..176 条标准速度成功入队 ACK，已明显降低重复发送。
- 最终里程计 `(0.53200,-0.00085,-0.01518)`，新反馈四轮全部 0 RPM，
  连续满足停车条件后退出所有测试节点和独立 master。
- 无主机发送背压，socket 只打开一次；9 条错误/状态通知包含正常状态通知。
  CRC/格式/填充错误计数为 0，不能理解为 CAN 无错误。
  最终 can0 为 UP/ERROR-ACTIVE，不能否定运行时捕获的位错误。

**本轮 ROS 调整没有修复运动时的通信故障。**保留逐轮调度、重复目标合并作为
发送压力控制；不能将其作为路线已通过的依据。后续需要核查 CAN1 链路、
终端/接地/供电、电机运行时干扰，或结合实际运行固件的内部证据继续定位。
本次遵守仅处理 ROS 的范围，没有修改 STM32。

`last_protocol_location` 诊断及显性/隐性位失败日志；后续正常控制器状态通知
