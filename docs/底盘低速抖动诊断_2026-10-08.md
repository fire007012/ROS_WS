# 底盘低速抖动诊断（2026-10-08）

当前可以确认：3 RPM 的不稳定并非只出现在路径跟踪时。固定目标、降低命令发送频率、
降低命令加速度，以及绕过 STM32 自定义速度解析使用原生透传后，速度波动仍存在。
定位方向为电机驱动器低速闭环与负载匹配，同时共用 CAN 链路的错误计数仍增长，
尚不能断言某个 PI 参数、刚性、机械摩擦或通信因素是唯一根因。

上一轮将转向速度提高到约 9 RPM，缓解了路径转向顿挫；这没有根治 3 RPM 的低速表现。
本轮没有修改上位生产代码、STM32 文件或驱动器存储/运行配置。
对比中只改变启动诊断进程的发送频率、运动命令加速度和传输路径。

## 协议和参数实读

ROS→STM32 标准 0x100 的 cmd=1 是整 RPM，现有上位端使用 `lround()`，
STM32 将整 RPM 乘 10，生成驱动器原生 F6。驱动器原生 X 协议支持 0.1 RPM。
这会使小幅变速和小于 0.5 RPM 的输入量化，但固定 3 RPM 下仍有波动，
不能把本轮问题仅归因于速度取整。

通过只读命令查询地址 1–4，结果如下：

| 参数 | 四个驱动器读取结果 |
| --- | --- |
| 固件返回版本值 | 205（0x00CD） |
| 运行模式 | FOC 闭环 |
| 细分 / 细分插补 | 16 / 开启 |
| 速度环 Kp / Ki | 15600 / 26（与手册 Y42 默认值一致） |
| 梯形 / 直通位置环 Kp | 126640 / 126640 |
| 刚性系数 | 384 |
| 闭环最大电流 | 4000 mA（手册默认为 3000 mA，差异本身不能证明故障） |

| 驱动器自身心跳保护 | 0 ms（关闭；本次仍由上位与 STM32 保护） |

原始参数回复完整，包含 CAN 多包重组和尾字节校验。PI、刚性等参数没有写入或修改。
静止供电读数约为 23.70–24.21 V。原始配置也保留在记录中，供后续单电机调参备份使用。

## 架空固定 3 RPM 对比

每项四轮同向 -3 RPM 运行约 6 秒，去掉前 1 秒，使用真实 0x35 回包统计；
另以约 20 Hz 查询地址 1 的 0x36 角度，按至少 0.25 秒区间差分计算速度。
实际目标固定，不使用路径跟踪、规划或速度仲裁。

| 测试 | 四轮 0x35 速度标准差平均值（RPM） | 地址 1 角度差分均速（RPM） | 地址 1 角度差分速度标准差（RPM） |
| --- | --- | --- | --- |
| 自定义命令，50 Hz，50 RPM/s | 0.962 | -3.036 | 0.285 |
| 自定义命令，10 Hz，50 RPM/s | 1.020 | -3.029 | 0.361 |
| 自定义命令，10 Hz，5 RPM/s | 1.109 | -3.040 | 0.287 |
| 原生 F6 透传，约 20 Hz，50 RPM/s | 1.138 | -3.010 | 0.331 |

原生试验只透传运动指令，使用实际标准心跳和四轮反馈保护，额外检查逐轮 F6 ACK。
原生帧绕过 STM32 的自定义速度解析，但仍经过同一 CAN1、STM32 转发和 CAN2，
不能据此排除共用传输链路的全部问题。

这些是短时对比，结果不支持把降低发送频率或加速度当作当前低速波动的修复办法。
位置平均速度接近目标，说明不是整体比例编码错误；位置差分波动也需结合接收时延、
角度量化和现场观察判断，不能直接等同于所有机械瞬时速度变化。
原生 3 RPM 时，地址 1 供电采样为 24.160–24.211 V，相电流采样 14–155 mA；
本轮未见明显供电压降，但低频 CAN 采样不能排除更短的电气瞬态。

每项结束均发送零目标/急停并确认新速度回包停车。
最终四轮 `[0.0, -0.3, 0.4, 0.0]` RPM，已停车，所有诊断节点和 ROS master 已退出。

## 可修复性与后续定位

驱动器支持速度环 PI 和刚性调整，因此有软件调参改善空间；当前尚未实证哪组参数有效，
不能承诺仅修改上位端即可根治，或承诺任意低速都像 9–10 RPM 一样平滑。
合理下一步是选一个架空电机，备份当前参数，以不存储的临时参数逐项比较速度环 PI 和刚性，
同时记录角度、速度、相电流，结束恢复原值；若无改善，再核查编码器校准与机械阻力。
更细速度分辨率需要扩展 STM32 自定义协议或单独评估原生控制入口，不能只在 ROS 端改单位。
当前固定 3 RPM 试验已经说明，分辨率升级也不保证消除本轮抖动。

此外，本轮前 CAN error-warning/error-passive 为 242/22，结束后为 647/82；
bus-off/restarts 均为 0，最终 ERROR-ACTIVE，内核 RX/TX errors 与 dropped 均为 0。
控制器错误计数持续增长，需要核查连接、终端电阻、共地及传输稳定性，
其对采样时序或运动的影响尚未隔离。
